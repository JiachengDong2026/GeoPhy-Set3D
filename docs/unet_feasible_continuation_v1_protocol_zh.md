# U-Net 可行场预热后的原目标续训 v1

日期：2026-10-27（北京时间）。用户明确授权继续训练并在异常或不收敛时中断分析。

从本轮自己的 `case0_original_refinement/last.pt` 恢复模型、AdamW、cosine scheduler和RNG，保留200步自生成可行场预热及100步原目标训练的来源。追加最多400次原目标更新，每25步固定评价、保存checkpoint及完整场。原模型、K96/64³全部有效射线、FP32、固定train0 epoch0 A/B/H/E、lr2e-4/wd1e-4/clip1及cosine300不变，调度以原目标累计更新数每16步推进。续训不重置动量，不读取稠密目标或GT。CPU→GPU只改变计算设备，先核验相同权重的起点数值。

这是现有成功案例的续训检查，不是166案例正式训练；H属于原训练目标，E为同案例未输入的四个站位射线。本次用户授权监测误差及中断，E纳入早停监测，因此不再视为未经使用的最终测试集。仅报告固定末态，不用最佳E选权重。

停止规则（更新前固定）：

- loss/梯度/参数变化/评价出现非有限数，或梯度/真实参数变化为零：保存异常现场，停止。
- 任一分支均值<1e-8、近零体素比例≥95%、std/mean<0.05：停止并检查塌缩。
- 连续三个评价节点E>1.25×续训起点E：停止，分析同案例未见射线过拟合。
- 连续三个节点loss>2×起点且H>1.2×起点：停止，分析发散。
- 追加≥200步时，最近100步的四次评价平均loss和H，相对前100步的四次评价平均值均改善不足1%：停止，分析平台或恶化。
- 资源冲突时仅停止本任务，不干预其他用户进程；不自动重放，不延长400步上限。

使用既有全局UUID锁、间隔15秒双空闲快照、启动前复查和资源冲突监测。大文件写scratch，旧实验目录和历史NO_GO保持封存。初末场用独立NumPy重新积分复核；检查优化器累计step、scheduler、逐更新journal和冻结成果哈希。
