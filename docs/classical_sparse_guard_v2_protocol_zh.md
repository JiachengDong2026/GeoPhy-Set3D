# 稀疏场健康度判据修订 v2（单独协议，不改写 v1）

本补充在 v1 停止后、任何正式测试预测或 GT64 读取前登记。v1 在物理 epoch175 / 14525 次更新因连续两次体素饱和比例超过 95% 停止，原始 STOP_PERSISTENT_COLLAPSE、checkpoint、journal 和禁止测试状态全部保留。这个状态不能改称原协议 GO。

触发因素是 train2 的负 logit 背景，不是浓度接近 1：只读冻结 epoch166 best 的独立 NumPy 检查中，约 97.5% 低值体素只占预测浓度总和约 2.2%；近零体素（<1e-10）比例为零，空间 std/mean 显著非零，normal H 约 0.08、zero H 约 1。体素计数的饱和阈值混淆了稀疏背景与整个有效信号消失。此证据不证明 GT 精度，也没有使用 GT。

仅登记一次判据修订：保留 mean≥1e-8、nearzero<95%、std/mean≥0.05，仍以 p*(1-p)<4.54e-5 标识饱和位置，但其“有效信号饱和比例”改为 sum(p * saturation_mask)/sum(p)，固定上限仍为 95%。原按体素计数的饱和比例继续逐场记录，最后同时报告原判据与新判据。空场、空间常量、全低值、有效浓度自身饱和仍应失败；CPU 合成正反例及实际边界预测检查必须先通过。这是判据变化，不能表述成原协议未变。

从 v1 的完整 epoch175 边界独立复制 journal、metrics 并硬链接不可变 checkpoint，恢复全部模型、optimizer、scheduler 和 RNG，继续 epoch176..300。每轮仍83次更新，累计24900次物理更新；保留4980次预热及166案例场求解的额外预算。保持网络、输入、所有射线、64³/K96、FP32、batch2、原objective、优化器和cosine300不变，不重放更新，不搜索新学习率或架构。第176及每25轮监测；修订健康度连续两次失败即停止，数值异常立即保留现场。

该分支称 UNet3D-feasible-preheat-sparseguard-v2。它只按完整36Val H在累计300轮中选择best。完成后重新独立验证全部更新与完整36Val；再对固定Val0..3、train0..2执行A/B normal/zero/wrong的42完整场NumPy复核，使用既定H改善、测量收益和错配依赖阈值，正常场通过新健康度。旧健康度结果也必须披露。任一失败不启用测试。

只有上述检查通过，才执行既有35test×17layout，全部595预测封存后独立GT64评分，GT128禁读。测试源码除独立路径、来源哈希和方法标签外复用已审计实现。只在同一35案例与相同站位上，复用冻结主模型既有210个C1结果进行配对比较。不能用v2的成功推翻v1的停止结论，不能将其称为原始无预热协议的等预算基线。
