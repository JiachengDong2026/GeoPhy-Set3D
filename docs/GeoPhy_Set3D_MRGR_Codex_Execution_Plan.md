## 3. 当前多尺度 MRGR 的结构理解

已知探针实现中的多尺度上下文路径具有以下设计：

1.  原解码器先在 `32³` 特征上执行三个 32 通道残差块。
2.  将 32 通道特征降至 12 通道。
3.  使用平均池化得到 `16³` 局部特征。
4.  再池化至 `8³` 获取更粗尺度上下文。
5.  在 `16³` 上融合局部特征与上采样后的粗尺度特征。
6.  上采样回原始 `32³` 尺度，并映射回 32 通道。
7.  输出卷积零初始化，以残差方式加入原解码器特征。
8.  后续解码器再上采样至 `64³`，完成三维重建。

相关探针代码曾在 `scripts/probe_mrgr_multiscale_v1.py` 中使用
`MultiscaleContext` 与 `ContextDecoder`。**请以阶段 0
核实出的正式实现为准。**

这一结构的优点是参数增量较小、初始化时保持原模型输出不变，而且可以补充较大空间范围的上下文。其不足是尺度融合主要由固定结构和卷积特征决定，并没有显式利用每个体素的局部可观测性来决定尺度贡献。

OARI 中已经存在局部射线方向和可观测性描述。现有
`LocalObservabilityDescriptor` 由局部有效射线方向计算：

-   归一化特征值（3 个）；
-   各向同性比例（1 个）；
-   有效观测比例（1 个）。

这形成 5 维描述符。请核实其形状、归一化、mask
和数值边界；它描述的是射线方向覆盖情况，**不能直接宣称它是完整的 Fisher
信息矩阵、可辨识性证明或三维重建误差的可靠置信度**。

## 4. 首选候选：可观测性感知的多尺度融合（OCMSF）

### 4.1 研究假设

同一套多尺度特征不应在所有体素上以同样方式发挥作用：

-   观测方向充分、几何覆盖较好的区域，可能更适合使用细尺度特征恢复峰值、边缘和局部梯度。
-   观测方向单一或覆盖不足的区域，可能更需要稳定的粗尺度上下文；过强的细节修正可能放大伪影。
-   但不能简单预设"观测不足就一定要偏向粗尺度"。这个关系必须由匹配实验检验。

研究假设为：**使用局部几何可观测性来调节不同尺度特征的融合权重，可能在不显著增加参数和计算量的前提下，改善困难几何下的三维重建，并降低局部形态错误。**

### 4.2 候选公式

将各尺度特征对齐到 `32³`：

\[ `\tilde `{=tex}F\_{32}=F\_{32},`\qquad`{=tex}
`\tilde `{=tex}F\_{16}=`\operatorname{Up}`{=tex}(F\_{16}),`\qquad`{=tex}
`\tilde `{=tex}F_8=`\operatorname{Up}`{=tex}(F_8). \]

令每个体素的 5 维可观测性描述符为
(O(`\mathbf{x}`{=tex}))。候选门控网络生成尺度 logits：

\[ a_s(`\mathbf{x}`{=tex}) =
g_s!`\left`{=tex}(`\tilde `{=tex}F_s(`\mathbf{x}`{=tex}),O(`\mathbf{x}`{=tex})`\right`{=tex}),
`\qquad`{=tex} `\alpha`{=tex}*s(`\mathbf{x}`{=tex}) =
`\operatorname{softmax}`{=tex}*{s`\in`{=tex}{32,16,8}}a_s(`\mathbf{x}`{=tex}).
\]

融合结果：

\[ F\_{`\mathrm{fuse}`{=tex}}(`\mathbf{x}`{=tex}) =
`\sum`{=tex}\_{s`\in`{=tex}{32,16,8}}
`\alpha`{=tex}\_s(`\mathbf{x}`{=tex})`\tilde `{=tex}F_s(`\mathbf{x}`{=tex}).
\]

再将融合结果通过轻量映射形成残差：

\[ F\_{`\mathrm{out}`{=tex}} = F\_{`\mathrm{base}`{=tex}}+
`\Delta `{=tex}F\_{`\mathrm{OCMSF}`{=tex}}. \]

这只是候选方案，不是预先认定的正确设计。请先实现最小、可解释版本，不要同时引入残差
gate、方向性卷积、新损失和新的训练采样规则。

### 4.3 实现要求

1.  先核实正式多尺度分支的输入、插入位置、通道数和参数量。
2.  尽可能复用当前尺度特征和 OARI
    已计算的描述符，不重复执行昂贵的几何计算。
3.  在进入门控网络前对描述符做明确的 shape、dtype、finite 和 mask 检查。
4.  需要将描述符从 OARI 的每体素表示转换为正确的 `[B, C, D, H, W]`
    形式时，显式写出并测试 reshape/permute；不能依赖隐式广播。
5.  对不可见体素、padding 视角、空 mask 和极端输入定义稳定行为，保证无
    NaN/Inf。
6.  使用零初始化残差输出层，或等效机制，使新模型初始时与原多尺度模型输出逐位一致（如果底层算子无法保证逐位一致，必须说明并设置严格数值容差）。
7.  C0/C1 必须遵循现有的共享参数和前向协议；不得无意引入两套不同的
    decoder。
8.  不要修改既有训练目标、数据分割、归一化、投影器采样数、checkpoint
    选择规则或最终测试集协议。
9.  记录参数增量、推理耗时、峰值显存和训练耗时；不把单次 noisy smoke
    test 宣称为性能提升。
10. 保留旧模型、旧检查点与旧报告，新增候选必须使用全新、清晰命名的路径。
11. 候选的模型结构、配置、代码版本和所有实验产物必须有 manifest/hash
    关联。
12. 不得用 GT 参与自监督训练、候选选择或多尺度门控；GT
    只能在现有规定的独立评价阶段使用。

### 4.4 不要直接加入的内容

在 OCMSF 得到清楚的实验结果之前，不要同时加入：

-   空间反馈 gate；
-   新的局部细节卷积支路；
-   未经验证的多尺度物理损失；
-   额外的输运/扩散 PDE 约束；
-   新的站位采样策略；
-   训练时依赖 GT 的局部区域选择；
-   只针对当前失败案例硬编码的形态规则。

这些变化会让消融结果无法归因。若后续需要研究它们，应另立实验分支并保持一项变量变化。

-   同时记录训练步数和墙钟时间，不能把不同训练预算的结果当成纯结构比较。
-   预注册指标和门槛后再运行正式筛查，不根据结果修改门槛。

## 6. 分阶段实验协议与晋级门槛

### 阶段 1：正确性与零成本行为检查

不启动完整训练。先完成：

1.  模型构造与 state dict 加载检查。
2.  原多尺度与 OCMSF 的初始输出逐位比较，或在明确容差下比较。
3.  每个新增参数的梯度存在、有限且可更新。
4.  对全可见、部分可见、无有效射线、padding 视角及不同 batch size
    进行前向测试。
5.  检查输出形状、值域、mask 逻辑和 NaN/Inf。
6.  确认 C0/C1 的 decoder 权重共享方式与旧模型一致。
7.  确认训练阶段没有读取 GT 文件；检查 GT
    guard、数据访问日志或项目已有等效审计。
8.  记录参数量、峰值显存、完整目标前向/反向耗时。
9.  运行已有测试套件；新增单元测试覆盖形状、mask、恒等初始化和梯度。
10. 对比新增模块启用前后的 source/data/config hash。

**任何正确性测试失败都必须停止，不允许以短程指标抵消实现错误。**

### 阶段 2：短程匹配筛查

先根据现有机器资源确认可用 GPU
和其他进程，再决定短程实验规模。默认沿用项目已有的训练协议和完整训练预算的学习率前缀；如要缩小数据子集，必须固定案例并在报告中注明结果仅用于筛查。

建议优先用固定的、预先登记的训练/验证案例和至少一个配对种子完成短程筛查；确认实现与曲线稳定后，再扩展到完整的
166 train / 36 val 协议（以当前仓库真实 split 为准）。

短程实验应固定末轮评价，不在多个轮次中挑选最好结果。至少报告：

-   普通布局 heldout 投影相对 L1；
-   困难聚簇布局 heldout 投影相对 L1；
-   普通布局逐案例 P90；
-   聚簇多布局案例内平均值；
-   输出退化、峰值/方差异常、数值稳定性；
-   每轮耗时、峰值显存与训练步数；
-   案例配对差及不确定性区间。

**建议的预注册晋级门槛：**

1.  正确性与数值稳定性全部通过。
2.  普通布局 heldout 投影相对 L1 至少改善 1%（相对改善，而非百分点）。
3.  普通布局逐案例 P90 不恶化超过 2%。
4.  困难聚簇布局均值不恶化超过
    2%；若研究目标明确针对困难布局，可要求其改善，但必须同时满足普通布局门槛。
5.  训练/验证耗时比和显存符合预先声明的预算。
6.  不能出现输出坍缩、峰值明显失真或大批案例恶化。
7.  所有条件必须同时满足，不允许只凭某一个布局改善晋级。

以上是建议门槛。Codex 必须在实验前将最终门槛写入 protocol
JSON/Markdown；一旦开始运行，不得根据结果事后修改。

若筛查未通过，停止该候选，不自动追加同配置长训练。输出失败分析，决定是否修复实现或结束分支。

### 阶段 3：完整训练

仅当阶段 1 与阶段 2 都通过，并且人工明确授权后才开始。

-   使用当前正式训练协议和冻结配置。
-   不改变已有 loss、采样、预处理或模型选择指标。
-   记录所有随机种子、数据和源码哈希、配置、环境、GPU 型号、checkpoint
    和 optimizer/scheduler 状态。
-   如果从短程训练接续，必须恢复模型、优化器、调度器、随机状态和数据采样状态；不允许只加载模型权重却声称是同一次连续训练。
-   如果无法精确恢复训练状态，必须作为独立的全新训练运行。
-   不与其他正在运行的实验抢占资源，不擅自杀进程。
-   只用预先指定的验证指标选择 checkpoint。
-   不访问最终 test 集。
-   保留完整日志与失败退出原因。

### 阶段 4：冻结检查点后的独立评价

训练和模型选择结束后先冻结
checkpoint，再运行独立评价。遵循项目现有的数据访问和 GT guard 协议。

必须报告：

-   三维相对 L1、L2；
-   普通布局与困难布局的均值、中位数、P90 和最大误差案例；
-   逐案例配对差、改善案例数和 bootstrap 区间；
-   真实峰位置浓度比、峰值幅度误差、质心偏移；
-   高浓度区域 Dice（沿用项目现有阈值定义）；
-   输入投影和未输入/留出投影误差；
-   典型案例的同切面、同色标可视化；
-   圆环等分布外形态的失败情况；
-   参数量、推理耗时、训练耗时和峰值显存。

不得只展示模型表现最好的案例；保留预先登记的成功与失败案例。最终 test
集仅在开发决策冻结后，按项目正式协议使用。

## 7. 评价和统计要求

### 7.1 相对 L1 的定义必须明确

报告必须说明相对 L1 的分母、零值处理、有效射线 mask
和案例平均方式。不要混淆：

-   投影域相对 L1；
-   三维体素域相对 L1；
-   绝对改善百分点；
-   相对误差改善百分比。

例如，从 10.0% 降至 9.5% 是下降 0.5 个百分点，相对误差降低
5%；二者不能混写。

### 7.2 以案例为统计单位

若同一案例有多个布局或多个站位
draw，应先按照预先声明的规则在案例内汇总，再以案例为配对单位计算均值、区间和胜负数。不能把同一案例的多个布局当成互相独立的样本来人为增大样本量。

### 7.3 多种子与不确定性

正式论文主张应尽量基于至少 3 个配对种子。分别报告：

-   各种子的均值；
-   跨种子均值与离散程度；
-   每个案例的配对差；
-   案例层面的 bootstrap 区间；
-   若样本和实验数量允许，说明种子层面不确定性。

不要把单种子案例 bootstrap
区间写成"模型训练结果具有统计显著性"的充分证据。

### 7.4 形态与几何分层

至少分层讨论：

-   普通/分散观测；
-   聚簇观测；
-   视角数量变化；
-   高浓度峰值区域；
-   真实峰位置与质心；
-   分布外目标形态。

如果平均 L1 改善但峰位置、质心或高浓度区域明显变差，应如实报告为
trade-off，不能笼统宣称"整体重建质量全面提升"。

## 8. 训练目标和物理一致性：先保持不变

当前自监督路径的核心思路是使用分离的 A/B 输入重建与未输入 H
视角留出监督，并结合交叉投影、已观测投影和一致性项。请以当前代码中的实际目标函数和配置为准，核实每一项的精确权重。

在本任务第一轮 OCMSF 实验中：

-   不修改目标函数；
-   不修改物理投影器采样数；
-   不修改输入站位采样；
-   不修改数据归一化；
-   不改变输出分辨率；
-   不引入 GT 训练监督。

这样才能把观测到的差异归因于多尺度融合结构。

若后续考虑增加物理正则，必须单独立项，明确它解决的物理问题，定义量纲、边界条件、离散化方式和数值稳定性，并通过独立消融验证。不能只因为模型称为
physics-informed 就增加未经验证的 PDE 项。
